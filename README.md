# frpc-gui

[frp](https://github.com/fatedier/frp) 客户端的图形界面启动器。填写服务器 IP 和 Token 即可启动内网穿透，支持配置多条代理，协议可选 **TCP / UDP / HTTP / HTTPS**。

## 特点

- 零第三方依赖 —— 纯 `syscall` 调用 Win32 API，不用任何 GUI 库
- 体积小，单文件约 2.9 MB，无控制台窗口
- **深色模式**，标题栏、控件、列表全部跟随，可随时切换
- 支持高 DPI 屏幕，125% / 150% 缩放下界面清晰不模糊
- 多代理管理：添加、修改、删除、上移、下移，重名自动补全
- 三种方式指定 frpc.exe：自动探测 / 浏览选择 / 拖拽到窗口

## 使用方法

### 1. 下载 frpc.exe

到 [frp 官方 Releases](https://github.com/fatedier/frp/releases) 下载对应平台的压缩包，解出 `frpc.exe`。

### 2. 与本程序放在同一目录

```
frpc-gui.exe      ← 本程序
frpc.exe          ← 官方 frp 客户端
frpc-gui-data/    ← 首次运行自动生成，存放配置
```

### 3. 运行

双击 `frpc-gui.exe`：

1. 填写服务器 IP、端口（默认 7000）、Token
2. 点「添加」配置代理，选择协议类型：
   - **TCP / UDP** —— 填本地端口和**远程端口**
   - **HTTP / HTTPS** —— 填本地端口和**自定义域名**（多个用逗号分隔）
3. 点「保存并启动」

配置会保存在同目录的 `frpc-gui-data/config.json`，下次打开自动回填。

> **提示**：HTTP / HTTPS 代理没有「远程端口」。HTTP 流量走服务端 `frps.toml` 里配置的 `vhostHTTPPort`（默认 80）/ `vhostHTTPSPort`（默认 443），按域名（Host）路由，所以客户端只需要填**自定义域名**，并确保域名已解析到服务器 IP。

## 常见问题

### 打开后瞬间闪退（无窗口、无提示）

**如果你装了「游戏加加」（GamePP），这是它的问题，不是本程序的 bug。**

游戏加加会把自己的 `GPP64.dll` 注入到新启动的进程里，而该 DLL 存在一个空指针解引用缺陷，注入后约 200 毫秒就会让宿主进程崩溃。

**解决办法（任选其一）：**

1. 使用本程序时退出游戏加加 ← 最省事
2. 把 `frpc-gui.exe` 加入游戏加加的排除 / 白名单

**技术细节**（已通过调试器定位到指令级）：

```
异常码   : 0xC0000005（访问冲突，读）
出错地址 : GPP64.dll + 0x9E9C6
访问目标 : 0x0000000000000000
```

`GPP64.dll` 位于：

```
%LOCALAPPDATA%\GamePPSdk\1.2.1618.725\GPP64.dll
```

反汇编后可见，崩溃函数的同一个字段在两条分支里被使用，其中一条做了 NULL 检查、另一条漏了：

```asm
; flag != 0 的分支：有保护
0x9E979  test rdi, rdi        ; 检查是否为 NULL
0x9E97C  je   0x9E9E9         ; 是 NULL 就安全返回
0x9E980  mov  eax, [rdi]      ; 才解引用

; flag == 0 的分支：缺少保护
0x9E9C4  mov  ecx, [rbx]
0x9E9C6  mov  eax, [rdi]      ; 直接解引用 rdi（此时为 NULL）→ 崩溃
```

该字段由 GPP64.dll 在注入后异步初始化。注入刚完成时它仍是 NULL，而 DLL 立刻走了没有 NULL 检查的那条路径，于是必然崩溃。对于**注入早已完成**的进程（例如已经运行很久的程序），该字段已被填充，因此不会崩 —— 这也是为什么「新启动的程序会闪退、旧的一直没事」。

实测数据（2026-10，Win11 24H2）：

| 条件 | 结果 |
| --- | --- |
| 游戏加加运行中，启动本程序 | 崩溃点 10/10 命中 `GPP64.dll+0x9E9C6` |
| 检查注入与崩溃的对应关系 | 注入 = 必崩（11/11）；未注入 = 不崩（0 崩溃） |
| 游戏加加未运行 | 0/25 崩溃 |

**这一点本程序无法通过改代码规避** —— 崩溃发生在第三方 DLL 的初始化竞态中，不依赖本程序的任何行为。如果「退出游戏加加后仍然闪退」，那才是别的原因，请到 [Issues](https://github.com/LinZX1314/frpc-gui/issues) 反馈。

### 启动失败，日志提示 `unknown field`

frpc 默认开启严格配置校验（strict config）。不同版本的 frp 支持的配置项不同，请确认你使用的 frpc.exe 版本与生成的配置兼容。本程序已按 frp 0.71 的配置格式生成。

### HTTP 代理启动后访问不到

检查服务端 `frps.toml` 是否配置了 `vhostHTTPPort`，以及域名是否已解析到服务器 IP。

## 构建

需要 Go 1.21 或更高版本：

```bash
go build -trimpath -ldflags "-H windowsgui -s -w" -o frpc-gui.exe .
```

- `-trimpath` 去掉二进制中的本机源码路径
- `-H windowsgui` 去掉控制台窗口
- `-s -w` 去掉符号表和调试信息

运行测试：

```bash
go test ./...
```

# frpc-gui

[frp](https://github.com/fatedier/frp) 客户端的图形界面启动器。填写服务器 IP 和 Token 即可启动内网穿透，支持配置多条代理，协议可选 **TCP / UDP / HTTP / HTTPS**。

## 特点

- 零第三方依赖 —— 纯 `syscall` 调用 Win32 API，不用任何 GUI 库
- 体积小，单文件约 2.9 MB，无控制台窗口
- **深色模式**，标题栏、控件、列表全部跟随，可随时切换
- 支持高 DPI 屏幕，125% / 150% 缩放下界面清晰不模糊
- 多代理管理：添加、修改、删除、上移、下移，重名自动补全
- 三种方式指定 frpc.exe：自动探测 / 浏览选择 / 拖拽到窗口

## 使用方法

### 1. 下载 frpc.exe

到 [frp 官方 Releases](https://github.com/fatedier/frp/releases) 下载对应平台的压缩包，解出 `frpc.exe`。

### 2. 与本程序放在同一目录

```
frpc-gui.exe      ← 本程序
frpc.exe          ← 官方 frp 客户端
frpc-gui-data/    ← 首次运行自动生成，存放配置
```

### 3. 运行

双击 `frpc-gui.exe`：

1. 填写服务器 IP、端口（默认 7000）、Token
2. 点「添加」配置代理，选择协议类型：
   - **TCP / UDP** —— 填本地端口和**远程端口**
   - **HTTP / HTTPS** —— 填本地端口和**自定义域名**（多个用逗号分隔）
3. 点「保存并启动」

配置会保存在同目录的 `frpc-gui-data/config.json`，下次打开自动回填。

> **提示**：HTTP / HTTPS 代理没有「远程端口」。HTTP 流量走服务端 `frps.toml` 里配置的 `vhostHTTPPort`（默认 80）/ `vhostHTTPSPort`（默认 443），按域名（Host）路由，所以客户端只需要填**自定义域名**，并确保域名已解析到服务器 IP。

## 常见问题

### 打开后瞬间闪退（无窗口、无提示）

**原因：装了「游戏加加」的轻量版（GamePPLite）。解决办法是换成完整版。**

游戏加加轻量版会把自己的 `GPP64.dll` 注入到其他进程里，而该 DLL 在部分进程上会触发空指针解引用，导致被注入的进程在约 200 毫秒内崩溃。

**解决办法：**

> **卸载游戏加加轻量版，改用[完整版](https://gamepp.com/download.html)。**

已实测：完整版同样会注入 `GPP64.dll`，但被注入的进程**不再崩溃**。

| 游戏加加版本 | 注入 GPP64.dll | 本程序结果 |
| --- | --- | --- |
| 轻量版 3.7.63.725 | 是 | **崩溃 11/11** |
| 轻量版 3.7.68.819 | 是 | **崩溃**（多次测试均崩） |
| **完整版 3.7.70.1016** | 是 | **存活 10/10** ✅ |

也可临时用「退出游戏加加」或「把 `frpc-gui.exe` 加入排除名单」规避。

#### 技术细节

用调试器挂载到进程后捕获到的崩溃现场（轻量版，多次复现地址一致）：

```
异常码   : 0xC0000005（访问冲突，读）
出错地址 : GPP64.dll + 0x9ABB6
访问目标 : 0x0000000000000000
```

`GPP64.dll` 位于 `%LOCALAPPDATA%\GamePPSdk\<版本号>\GPP64.dll`。

反汇编崩溃点，可见同一字段在两条分支里被使用，其中一条做了 NULL 检查、另一条漏了：

```asm
; flag != 0 的分支：有保护
test rdi, rdi            ; 检查是否为 NULL
je   <安全返回>           ; 是 NULL 就退出
mov  eax, [rdi]          ; 才解引用

; flag == 0 的分支：缺少保护
mov  ecx, [rbx]
mov  eax, [rdi]          ; 8B 07，直接解引用 rdi（此时为 NULL）→ 崩溃
```

该分支在多个版本中都存在（`0x9E9C6` → `0x9ABB6` → `0x9AB82`，指令始终是 `8B 07`）。完整版并未删除这条指令，而是调整了初始化顺序，使该字段在使用前已被填充，因此不再触发。

#### 实测数据（2026-10，Windows 11 24H2）

| 测试项 | 结果 |
| --- | --- |
| 轻量版运行中启动本程序 | 崩溃点 10/10 命中 GPP64.dll 内同一地址 |
| 轻量版：注入与崩溃的对应关系 | 被注入 11 次全部崩溃；未被注入的不崩 |
| 轻量版换成 30 行空窗口测试程序 | 同样被注入、同样崩溃 |
| 游戏加加未运行 | 0/25 崩溃 |
| **完整版运行中启动本程序** | **被注入 10 次，存活 10/10** |

第三行说明：**这与本程序的功能逻辑无关** —— 一个几乎什么都不做的空窗口程序，在轻量版下也一样会崩。

如果你遇到的是**其他表现**的闪退（例如根本没装游戏加加，或换完整版后仍然闪退），那属于别的原因，请到 [Issues](https://github.com/LinZX1314/frpc-gui/issues) 反馈，并附上系统版本与复现步骤。

### 启动失败，日志提示 `unknown field`

frpc 默认开启严格配置校验（strict config）。不同版本的 frp 支持的配置项不同，请确认你使用的 frpc.exe 版本与生成的配置兼容。本程序已按 frp 0.71 的配置格式生成。

### HTTP 代理启动后访问不到

检查服务端 `frps.toml` 是否配置了 `vhostHTTPPort`，以及域名是否已解析到服务器 IP。

## 构建

需要 Go 1.21 或更高版本：

```bash
go build -trimpath -ldflags "-H windowsgui -s -w" -o frpc-gui.exe .
```

- `-trimpath` 去掉二进制中的本机源码路径
- `-H windowsgui` 去掉控制台窗口
- `-s -w` 去掉符号表和调试信息

运行测试：

```bash
go test ./...
```
